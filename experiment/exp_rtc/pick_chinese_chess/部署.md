## 启动RTC推理

1. 修改 policy.config 为目标config，注意是否为lora

2. 修改 policy.dir 为目标checkpoint的路径

```bash
XLA_PYTHON_CLIENT_MEM_FRACTION=0.95 uv run --no-sync scripts/serve_policy.py \
    --port=8000 \
    policy:checkpoint \
    --policy.config=pi05_piper_full_finetune_rtc \
    --policy.image-size=224 \
    --policy.dir=/media/ubun/16T/checkpoints/openpi-rtc/pick-chinese-chess-full-rtc
```

## 启动真机

首先要启动 can0 端口

```bash
# can0 up
sudo ip link set can0 down
sudo ip link set can0 type can bitrate 1000000
sudo ip link set can0 up
```

注意设置相机的序列号。异步 RTC 使用 `rtc_main.py`，不接受 `--open-loop-horizon`。

本机 checkpoint 的 `max_delay=4`；下面显式设置 `--rtc-delay=4`。30 Hz 时覆盖约 133 ms，
15 Hz 时覆盖约 267 ms，但降低频率会改变训练动作的播放速度，应结合数据采集频率评估。
客户端先做一次冷启动和 3 次预热推理，再发送动作；`--inference-timeout-s=30` 可按冷启动耗时调整。
不指定 `--rtc-delay` 时使用预热往返耗时加一 tick 估计，最大不超过训练范围。
若日志连续出现 `Discarding stale RTC response`，达到 `--max-consecutive-misses=3` 后会退出，
应先优化推理延迟或在训练支持范围内调整 delay。退出会断开 SDK 连接，并不等同于硬件急停。

uv run --no-sync examples/piper/rtc_main.py \
